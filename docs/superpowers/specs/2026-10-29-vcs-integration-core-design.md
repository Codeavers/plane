# VCS integration core (GitHub first): design

Status: draft for review. Task: CODEA-40. Sub-project 1 of 4.

## Goal

When a pull request references a Plane work item, Plane moves the work item through its workflow on its own:

- PR opened (not draft) → In Review, plus a comment with the PR link.
- PR merged into a base branch, and every PR linked to the work item is merged → Done, plus a comment.
- PR closed without merge → In Progress, plus a comment.

The behaviour is configurable per workspace with optional per-project overrides. The design is provider-agnostic: GitHub is the first provider, and GitLab and others are added as adapters without changing the core.

Success: opening a PR whose branch is `feat/CODEA-40-...` moves CODEA-40 to In Review with a link comment, and merging it into `develop` or `main` moves it to Done. Adding GitLab means writing one adapter module.

## Decisions

| Topic | Decision |
|---|---|
| Location | Inside our Plane fork (`Codeavers/plane`), backend module `plane/integrations/vcs/` |
| Connection | Inbound webhook signed with a shared secret (HMAC). No provider tokens are stored. No write-back to the provider. |
| Scope | One connection per workspace (an organization webhook covers all repos). Workspace-level rules with an optional per-project override. The project comes from the identifier prefix (`CODEA-40` → project `CODEA`). |
| Target state | State name, falling back to a state group when the name does not exist in the project |
| Several PRs per work item | Done only when every linked PR is merged |
| Processing | Asynchronous (Celery). The webhook responds 202 immediately. |

## Sub-projects

1. Core and GitHub (this spec): models, engine, GitHub adapter, webhook, configuration API.
2. Configuration screens in workspace and project settings, plus the PR list in the work item view.
3. Fork deployment: CI builds images in GHCR and tasks.codeaver.com switches to them. Without this, sub-projects 1 and 2 do not run in production.
4. GitLab adapter, then further providers (Bitbucket, Gitea, Azure DevOps).

Out of scope for sub-project 1: UI, writing back to the provider (PR comments, checks), automatic unlinking, provider OAuth apps.

## Architecture

Module `apps/api/plane/integrations/vcs/`:

| Unit | Responsibility | Depends on |
|---|---|---|
| `events.py` | `PullRequestEvent` dataclass: provider, delivery id, repo full name, number, url, title, body, source branch, base branch, action (`opened`, `reopened`, `ready_for_review`, `converted_to_draft`, `closed`, `merged`, `edited`, `synchronize`), draft flag, author login, provider `updated_at` | nothing |
| `providers/base.py` | `VcsProvider` interface: `key`, `verify(headers, raw_body, secret) -> bool`, `parse(headers, payload) -> PullRequestEvent | PingEvent | None`, `delivery_id(headers) -> str`, `settings_schema()` | `events` |
| `providers/registry.py` | Strategy registry: `register(provider)`, `get(key)`, `all()` | `base` |
| `providers/github.py` | GitHub adapter: `X-Hub-Signature-256` HMAC-SHA256 with constant-time compare; `X-GitHub-Delivery`; maps `pull_request` actions (`closed` + `merged=true` → `merged`); `ping` → `PingEvent` | `base`, `events` |
| `settings.py` | Settings schema (versioned), defaults, validation, and `effective_settings(connection, project)` = workspace settings deep-merged with the project override | nothing |
| `matchers.py` | ID extraction chain: each matcher has a `source` (`branch`, `title`, `body`) and a regex; returns `(identifier, sequence_id, source)` tuples | `settings` |
| `rules.py` | Rule engine: selects the rules for an event action, evaluates conditions, returns actions | `settings`, `events` |
| `actions.py` | Command objects: `SetState`, `Comment`; each `execute(issue, event, context) -> ActionResult` | Plane models, `issue_activity` |
| `service.py` | Orchestration for one delivery: normalize, sync PR, link, evaluate, act, record summary | everything above |
| `webhook.py` | Public endpoint, signature check, delivery persistence, enqueue | `registry`, models |
| `tasks.py` | Celery task `process_vcs_delivery(delivery_id)` with retries | `service` |
| `views.py`, `serializers.py`, `urls.py` | Configuration API (app API) | models, `settings`, `registry`, `matchers` |

A new provider adds one module under `providers/` and registers it; nothing else changes.

## Settings schema (version 1)

```json
{
  "version": 1,
  "matchers": [
    {"source": "branch", "enabled": true, "pattern": "\\b([A-Z][A-Z0-9]{1,11})-(\\d+)\\b"},
    {"source": "title", "enabled": true, "pattern": "\\b([A-Z][A-Z0-9]{1,11})-(\\d+)\\b"},
    {"source": "body", "enabled": true, "pattern": "(?i:fixes|closes|resolves|refs)\\s+([A-Z][A-Z0-9]{1,11})-(\\d+)\\b"}
  ],
  "base_branches": ["main", "master", "develop", "preview"],
  "rules": [
    {"on": ["opened", "reopened", "ready_for_review"], "when": {"draft": false, "from_groups": ["backlog", "unstarted", "started"]},
     "actions": [{"type": "set_state", "state": "In Review", "fallback_group": "started"}, {"type": "comment", "template": "pr_opened"}]},
    {"on": ["merged"], "when": {"base_branch": "base_branches", "all_linked_merged": true, "from_groups": ["backlog", "unstarted", "started"]},
     "actions": [{"type": "set_state", "state": "Done", "fallback_group": "completed"}, {"type": "comment", "template": "pr_merged"}]},
    {"on": ["closed"], "when": {"from_groups": ["started"]},
     "actions": [{"type": "set_state", "state": "In Progress", "fallback_group": "started"}, {"type": "comment", "template": "pr_closed"}]}
  ],
  "comment_templates": {
    "pr_opened": "PR <a href=\"{url}\">{repo}#{number}</a> opened: {title}",
    "pr_merged": "PR <a href=\"{url}\">{repo}#{number}</a> merged into {base_branch}",
    "pr_closed": "PR <a href=\"{url}\">{repo}#{number}</a> closed without merge"
  }
}
```

Rules:

- Matcher patterns must have two capture groups (identifier, number). They are compiled and validated on save, with a length limit and a timeout guard against catastrophic regexes.
- `when.base_branch` takes `"base_branches"` (the list above) or an explicit list of globs.
- `when.from_groups` is the safety guard: an action only moves a work item whose current state group is listed. Reopening a PR never moves a cancelled work item.
- `when.all_linked_merged`: every non-deleted PR linked to the work item is in state `merged`.
- Template values are escaped. Available fields: `url`, `repo`, `number`, `title`, `base_branch`, `source_branch`, `author`.
- Overrides deep-merge objects and replace lists.

## Event flow

1. **Receive (synchronous, target under 1 s).** `POST /api/integrations/vcs/<provider>/<connection_id>/`. No session or API key; authentication is the signature only. Rate limited per connection.
   - Unknown or inactive connection, or provider mismatch → 404 with no detail.
   - Invalid or missing signature → 401; nothing is stored.
   - Duplicate `delivery_id` → 200 without reprocessing.
   - Otherwise store `VcsDelivery(status=received)`, enqueue `process_vcs_delivery`, respond 202.
2. **Normalize (Celery).** The adapter parses the payload. `ping` sets `verified_at`. Irrelevant events and repos outside `repo_filter` → `ignored`.
3. **Sync the PR.** Upsert `VcsPullRequest`. If the event's `updated_at` is older than `provider_updated_at`, update nothing and record `stale`; links and rules still run only when the event is not stale.
4. **Link.** Run the enabled matchers in order; resolve each `(identifier, sequence_id)` to a work item in the connection's workspace (`project__identifier`, `sequence_id`). Skip projects excluded by `only_enabled_projects` or with a disabled override. Create missing `VcsPullRequestLink` rows. Existing links are kept even if the ID disappears from the PR.
5. **Evaluate.** For each linked work item, compute the effective settings for its project and select the rules whose `on` contains the event action and whose `when` holds.
6. **Act.** Per work item, in its own transaction:
   - `SetState` resolves the target state in the work item's project by name, then by `fallback_group` (lowest sequence). No match → skipped, recorded. Already in the target state → no-op. Otherwise update the state through the same path the public API uses, with `issue_activity` and the bot user as actor, so activity and notifications behave as for any change.
   - `Comment` renders the template and posts it as the bot user. It is skipped if a comment for the same PR and action already exists on the work item (`external_source="vcs"`, `external_id="<connection>:<repo>#<number>:<action>"`).
7. Mark the delivery `processed` with the summary.

## Errors

- Transient errors (database, broker): Celery retries 3 times with exponential backoff, then `failed` with the error stored.
- A failure on one work item does not stop the others in the same delivery; it is recorded in the summary.
- Malformed or unsupported payloads: `failed` without retry.
- Admins can redeliver a stored delivery from the API.

## Configuration API (app API, `/api/workspaces/<slug>/`)

| Endpoint | Methods | Permission |
|---|---|---|
| `vcs-providers/` | GET: registered providers and their settings schema and defaults | workspace member |
| `vcs-connections/` | GET, POST | workspace admin |
| `vcs-connections/<id>/` | GET, PATCH, DELETE | workspace admin |
| `vcs-connections/<id>/rotate-secret/` | POST | workspace admin |
| `vcs-connections/<id>/deliveries/` | GET (paginated) | workspace admin |
| `vcs-connections/<id>/deliveries/<delivery_id>/redeliver/` | POST | workspace admin |
| `vcs-connections/<id>/test-match/` | POST `{branch, title, body}` → matched work items | workspace admin |
| `projects/<project_id>/vcs-settings/` | GET, PUT | project admin |
| `projects/<project_id>/issues/<issue_id>/pull-requests/` | GET | anyone who can view the work item |

POST on a connection returns the webhook URL and the secret once; afterwards the secret is never returned, only rotated. Every query is bound to the URL workspace (and project), following the scoping pattern of the recent upstream security fixes.

## Testing

Unit (no database):

- GitHub signature: valid, invalid, missing, wrong algorithm.
- GitHub normalization from recorded payload fixtures: opened, draft opened, ready_for_review, reopened, closed with and without merge, edited, ping, unsupported event.
- Matchers: each source, custom patterns, invalid patterns rejected, duplicates collapsed.
- Settings: validation errors, deep merge of overrides.

Integration (database, Celery eager):

- Full webhook path for each default rule.
- Several PRs per work item: Done only after the last merge.
- Merge into a non-base branch does not set Done.
- `from_groups` keeps a cancelled work item untouched.
- Duplicate delivery is idempotent; out-of-order events do not regress PR state.
- Repo outside the filter is ignored; missing target state is skipped and recorded.
- Workspace isolation: an identifier from another workspace is never touched.
- Permissions on every configuration endpoint; the webhook accepts only a valid signature.

End to end: local stack, a real GitHub test repository webhook through a tunnel, or replayed payloads signed with the connection secret.
